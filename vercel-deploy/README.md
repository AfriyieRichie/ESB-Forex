# Setup Dashboard — live deployment

A personal, password-gated dashboard that **follows the live forex market** and
**alerts you on Telegram** when a wammie/moolah setup that passes your checklist
forms — for **$0**.

## How it works (no server to keep awake)

```
        ┌─────────────────── GitHub Action (cron, every 2h) ──────────────────┐
        │  refresh free Dukascopy data  →  run the checklist detector          │
        │        │                                   │                          │
        │        │                                   ├──► NEW setup? ──► Telegram alert 📲
        │        │                                   │                          │
        │        └──► render charts + signals.json ──┴──► git commit ───────────┼──► Vercel
        └─────────────────────────────────────────────────────────────────────┘        │
                                                                                        ▼
                                                    Static dashboard (private, password-gated)
                                                    click a signal → drawn setup + checklist
```

The cron does all the work on a free GitHub-hosted runner (no memory limits, never
sleeps). Vercel just serves static files, so it can't crash. Your **journal lives
in your browser** (localStorage) — it's never on the server.

**No market API key, no account, no cost.** Data comes free from Dukascopy. For
H4/D1 setups a ~1-hour delay is irrelevant.

## The system's files (what to put in the repo)

```
src/fxlab/**              the detector, zone builder, Dukascopy downloader, chart renderer
scripts/live_scan.py      the cron's payload: refresh → detect → publish → alert
setup-dashboard/scanner.py the basket scan + chart rendering used by live_scan
vercel-deploy/            what Vercel serves ↓
  public/index.html         the dashboard
  public/signals.json       generated by the cron
  public/charts/*.png       generated by the cron
  vercel.json               static config
.github/workflows/live-scan.yml   the cron
pyproject.toml            dependencies (so the Action can install fxlab)
.gitignore                keeps secrets + data OUT of the repo
```

`data/`, `.venv/`, and **every `.env`** are gitignored — see the safety check below.

## One-time setup (~15 min)

### 1. Push to GitHub (private repo)

```bash
cd <this-project>
git init && git add -A
git status                       # ← LOOK: no .env, no data/ should be listed
git commit -m "setup dashboard"
git branch -M main
git remote add origin git@github.com:<you>/<repo>.git
git push -u origin main
```

> **Safety check before the first push** — confirm no secret is staged:
> ```bash
> git ls-files | grep -E "\.env$"      # must print NOTHING
> ```
> If it prints anything, stop and remove it: `git rm --cached <file>`. Your
> `trading-webapp/.env` holds a live API key — it must never appear here.

### 2. Telegram alerts (2 min)

1. In Telegram, message **@BotFather** → `/newbot` → copy the **bot token**.
2. Message **@userinfobot** → copy your numeric **chat id**.
3. Send your new bot any message once (so it's allowed to DM you).
4. In the GitHub repo: **Settings → Secrets and variables → Actions → New repository secret**, add:
   - `TELEGRAM_BOT_TOKEN` = the bot token
   - `TELEGRAM_CHAT_ID` = your chat id

### 3. Turn the cron on and seed it

- **Actions** tab → enable workflows if prompted → open **live-scan** → **Run workflow**.
- The first run downloads ~2 years of history (a few minutes); later runs are seconds.
- You should get a Telegram message for each current setup. From then on it runs
  itself every 2 hours.

### 4. Deploy the dashboard to Vercel

1. [vercel.com](https://vercel.com) → **Add New → Project** → import your repo.
2. **Root Directory** → set to `vercel-deploy`.
3. Framework preset **Other**, no build command (it's static — `vercel.json` handles it).
4. **Deploy.** Every cron commit auto-redeploys it.

### 5. Set your password

The dashboard is gated by a SHA-256 hash in `public/index.html` (default password:
`changeme`). Change it:

```bash
uv run python -c "import hashlib;print(hashlib.sha256('YOUR_PASSWORD'.encode()).hexdigest())"
```

Paste the output over `GATE_HASH` in `public/index.html`, commit, push.

> **Honest note on the gate:** it hides the UI but the data files are still
> reachable by direct URL — it keeps casual visitors out, not a determined one.
> For **real** protection (free), put **Cloudflare Access** in front of your Vercel
> domain: Cloudflare Zero Trust → Access → add your Vercel domain as an app →
> allow only your email. That gates *everything*, including the JSON and PNGs.

## Keeping it fresh

- **Automatic:** the cron runs every 2 hours. To change cadence edit the `cron:`
  line in `.github/workflows/live-scan.yml` (`"20 * * * *"` = hourly — use only on
  a public repo for unlimited Actions minutes, or if you don't mind the usage).
- **Manual / local:** you can also refresh from your own machine anytime:
  ```bash
  uv run python scripts/live_scan.py        # refresh + detect + publish + alert
  cd vercel-deploy && git add -A && git commit -m refresh && git push
  ```

## What it is — and isn't

- **Radar, not autopilot.** The detector only verifies the *mechanical* rules
  (established zone, two touches, spacing, reversal candle, R:R). The drawn setup
  and your own read decide the trade. The dashboard's right-hand checklist is the
  discretionary half you confirm yourself.
- Setups older than a few bars may already have moved — the timestamp is shown.
- The edge here is **discipline and consistency**, not a magic signal.
